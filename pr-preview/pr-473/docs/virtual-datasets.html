Virtual datasets with xarray¶

Many netCDF or HDF5 files become one virtual dataset, which VirtualiZarr builds and refkv saves as one small archive that records where each chunk lives in the original files. xarray opens the archive as an ordinary lazy dataset, and reads each chunk from the file it came from: no data is copied.

Install¶

pip install "refkv[virtualizarr]" xarray h5py h5netcdf fsspec aiohttp

The virtualizarr extra installs VirtualiZarr, which refkv.ReferenceStore.from_virtualizarr and refkv.virtualizarr need, and with it xarray and obspec_utils; the zarr extra, zarr-python, with which refkv.zarr opens a store for xr.open_zarr; and the obstore extra, obstore, whose S3Store reads the bucket. refkv itself imports neither xarray nor obstore. The rest are for the example: h5py for VirtualiZarr’s HDF5 parser, and h5netcdf, fsspec and aiohttp for xarray to read a netCDF file over HTTPS and check the archive’s values; xarray brings pandas. Without the extras, refkv reads and writes archives, local or at http(s) URLs, and holds a ReferenceStore built from a mapping, without Zarr or obstore; refkv[zarr] alone adds refkv.zarr, and refkv[obstore] alone the stores for registry=. (In a clone of this repository, uv sync installs all of these.)

An example: five years of sea surface temperature¶

NOAA OISST v2.1 is one netCDF file per day on a public S3 bucket. The example zarrifies the 1st of each month from 2015 to 2019, 60 files, and saves them as oisst.vzip. It then reopens the archive with xarray, computes the yearly mean temperature over the Niño 3.4 region, and checks one day against the netCDF file. It runs in 1 to 1.5 minutes, about 40 s of it to zarrify the files, and reads about 7 MB of metadata and 40 MB of data. The file is examples/oisst.py:

"""Five years of NOAA OISST v2.1 as one virtual dataset, saved as a vzip archive.

The daily netCDF files stay on AWS: the archive records where each chunk lives,
and xarray reads the chunks from those files. This takes the 1st of each month,
60 files: 1 to 1.5 minutes in all, about 40 s of it to zarrify them.
"""

from concurrent.futures import ThreadPoolExecutor
from functools import partial

import fsspec
import numpy as np
import pandas as pd
import virtualizarr as vz
import xarray as xr
from obspec_utils.readers import BlockStoreReader
from obspec_utils.registry import ObjectStoreRegistry
from obstore.store import S3Store  # refkv[obstore], which refkv[virtualizarr] includes
from virtualizarr.parsers import HDFParser

import refkv
import refkv.zarr

bucket = "noaa-cdr-sea-surface-temp-optimum-interpolation-pds"
days = pd.date_range("2015-01-01", "2019-12-31", freq="MS")  # freq="D" for every day
urls = [f"s3://{bucket}/data/v2.1/avhrr/{d:%Y%m}/oisst-avhrr-v02r01.{d:%Y%m%d}.nc" for d in days]


class EightThreads(ThreadPoolExecutor):  # parallel= takes a class, which VirtualiZarr instantiates
    def __init__(self):
        super().__init__(max_workers=8)


# 1. Zarrify the files, 8 at a time, reading only their metadata, and concatenate along time.
registry = ObjectStoreRegistry({f"s3://{bucket}": S3Store(bucket, region="us-east-1", skip_signature=True)})
parser = HDFParser(reader_factory=partial(BlockStoreReader, block_size=2**16))
vds = vz.open_virtual_mfdataset(
    urls, registry=registry, parser=parser, parallel=EightThreads, combine_attrs="drop_conflicts"
)

# 2. Save it as a vzip archive, naming the files by their public HTTPS URLs.
store = refkv.ReferenceStore.from_virtualizarr(vds, rewrite_urls=refkv.public_s3_url)
print(store.save_vzip("oisst.vzip"))

# 3. Reopen it with xarray: the yearly mean SST over the Nino 3.4 region, weighted by area.
stats = refkv.Stats()
ds = xr.open_zarr(refkv.zarr.open("oisst.vzip", stats=stats))
nino34 = ds.sst.sel(lat=slice(-5, 5), lon=slice(190, 240)).load()  # read each chunk once
mean = nino34.weighted(np.cos(np.deg2rad(nino34.lat))).mean(["lat", "lon", "zlev"])
print(mean.groupby("time.year").mean().to_series().round(2))
print(f"read {stats.external_bytes / 1e6:.0f} MB in {stats.external_requests} requests to the netCDF files")

# 4. Check the last day against the netCDF file itself (float32: see troubleshooting).
with fsspec.filesystem("https").open(refkv.public_s3_url(urls[-1])) as f:
    direct = xr.open_dataset(f, engine="h5netcdf").sst.sel(lat=slice(-5, 5), lon=slice(190, 240))
    np.testing.assert_array_equal(nino34.sel(time=direct.time).astype("float32"), direct)
print("the archive's values equal the netCDF file's on", days[-1].date())

year
2015    28.34

What each step does:

  1. Zarrify. open_virtual_mfdataset reads each file’s HDF5 metadata, records each chunk as a byte range, and concatenates the files along time. The S3Store reads the public bucket without credentials, the HDFParser reads in 64 kB blocks rather than whole files (troubleshooting), and EightThreads reads 8 files at a time (scaling up). combine_attrs="drop_conflicts" drops the attributes that differ between files (id, date_created, date_modified, time_coverage_*), rather than keeping the first file’s.

  2. Save. from_virtualizarr turns the virtual dataset into a store: Zarr metadata, the coordinates as bytes, and each chunk as a reference. rewrite_urls=refkv.public_s3_url names each file by its public HTTPS URL (publishing). save_vzip writes the archive and summarizes it.

  3. Compute. refkv.zarr.open opens the archive as a read-only Zarr store for xr.open_zarr, which reads chunks from the netCDF files, at most 8 requests at a time. The files’ chunking stays: a chunk of sst is a whole day’s global field, 720×1440, about 0.65 MB, so even one grid cell costs that per day (a year of one cell read 239 MB). The mean is weighted by cos(latitude), each cell’s relative area; within ±5° that moves it by at most 0.01 °C.

  4. Check. The netCDF file gives the same values, once the archive’s float64 is cast to float32, which is exact (troubleshooting).

Zarrifying with refkv, for VirtualiZarr¶

VirtualiZarr builds a virtual dataset with a parser for the file’s format. refkv’s refkv.virtualizarr.RefkvParser is one parser for every format refkv can zarrify (the list): it zarrifies the file, read through the registry VirtualiZarr gives it, and hands VirtualiZarr the result as a ManifestStore. The file is examples/refkv_parser.py:

"""A netCDF file opened as a VirtualiZarr virtual dataset through refkv's parser.

RefkvParser zarrifies the file with refkv and hands VirtualiZarr the result as a ManifestStore,
so open_virtual_dataset takes any file refkv can zarrify. This writes a small netCDF file into
the current directory, so it runs offline.
"""

from pathlib import Path

import numpy as np
import virtualizarr as vz
import xarray as xr
from obspec_utils.registry import ObjectStoreRegistry
from obstore.store import LocalStore

from refkv.virtualizarr import RefkvParser

path = Path("temperature.nc").resolve()
expected = xr.Dataset(
    {"t": (("time", "x"), np.arange(12.0).reshape(3, 4), {"units": "K"})},
    coords={"time": [0, 1, 2]},
)
expected.to_netcdf(path, engine="h5netcdf", encoding={"t": {"chunksizes": (1, 4)}})

registry = ObjectStoreRegistry({"file://": LocalStore()})
with vz.open_virtual_dataset(path.as_uri(), registry=registry, parser=RefkvParser(),
                             loadable_variables=["time"]) as vds:
    print(vds["t"].data.manifest.dict()["0.0"])  # the first chunk: a byte range of the file

# The parser's ManifestStore is also a Zarr store, which xarray reads directly.
ds = xr.open_zarr(RefkvParser()(path.as_uri(), registry), zarr_format=3, consolidated=False)
np.testing.assert_array_equal(ds["t"], expected["t"])
print("the virtual dataset's values equal the file's")

It prints the first chunk’s manifest entry, a byte range of the file, then the virtual dataset's values equal the file's.

RefkvParser takes group= and skip_variables=, as VirtualiZarr’s parsers do, policy=, the refkv.Policy refkv reads the file and its chunks under, and layout=, the layout plugin to zarrify with. Its default is the refkv.virtualizarr layout, which presents an HDF5, netCDF-4, netCDF3, FITS, ENVI, Zarr v2 or zipped Zarr v3 file as VirtualiZarr’s own parsers present it: the same array names, dimension names and attributes, without refkv’s declarations. A file of another format, which that layout does not read, or one the layout refuses (a FITS image with BSCALE = 0), is written as refkv’s own output, and layout=None asks for refkv’s own output for every file. Either way the file is read once: a layout and refkv’s own output are two projections of the one parse. The parser leaves out refkv’s refkv_source group, which describes the file, not its data. Given an ENVI raster’s data file, as VirtualiZarr names it, the parser reads the .hdr header beside it, which is how refkv names the raster, found as ENVIParser finds it.

refkv.virtualizarr.manifest_store(store, registry) is the conversion on its own: the ManifestStore of any reference store, a zarrify result or a saved archive refkv.open opened, with the same group= and skip_variables=. A manifest entry is one byte range, so a chunk that is one range of a file becomes an entry, and the rest is inlined into the manifest: bytes values, references whose bytes are all in the store, and chunks made from several ranges (a netCDF variable-length string chunk, a JPEG tile with its shared tables), which are read during the conversion. Each file a manifest names is checked against the store’s policy first, since VirtualiZarr reads it later without refkv. The pins and checksums a store keeps for its sources have no place in a manifest, and are dropped.

just virtualizarr-parity (conformance/virtualizarr/test_parity.py) compares RefkvParser with VirtualiZarr’s own parsers on generated files, for each array’s shape, data type, fill value, dimension names, attributes, chunk byte ranges and values; the differences that remain are listed there, each with the item of refkv#271 that tracks it.

Scaling up¶

  • Every day. freq="D" takes every day. A year of daily files took 156 s to zarrify with 8 threads, about 0.4 s per file, against about 1.2 s per file one at a time. parallel= takes an executor class and instantiates it with no arguments, hence the EightThreads subclass, which keeps the host to 8 connections.

  • Reuse the archive. That is the point of saving it: steps 3 and 4 rerun from refkv.zarr.open("oisst.vzip") without zarrifying again, so guard steps 1 and 2 with if not Path("oisst.vzip").exists(): while you iterate.

  • The page index. Without one, a reader loads the whole central directory at open, about 125 bytes per key. A year of daily OISST is 1,837 keys in a 263 kB archive: no index needed. At 259,200 keys, the directory was 18.8 MB, and a page index cut opening to 2 requests and 115 kB (design/COMPARISON.md). Once the directory passes a few MB, tens of thousands of keys, save with store.save_vzip("oisst.vzip", page_size=65536) (spec §12, Page index).

  • The perfect-hash binding. For a store of hundreds of thousands of keys, store.save_phkv("oisst.phkv") writes the draft phkv binding instead (spec): a perfect hash of the keys, so that opening the file and reading the first key takes 3 requests of about 516 KiB at 10^5 and 10^6 keys, and each later key one or two, fewer than a paged archive takes (benchmarks). refkv.open("oisst.phkv", binding="phkv") and refkv.zarr.open("oisst.phkv", binding="phkv") read it with the same options as an archive. It is not a ZIP file, so ZIP tools cannot open it.

  • Requests. refkv.zarr.open(..., max_concurrency=16) allows more requests in flight, and max_concurrency=None removes the cap. Respect the host’s limits.

  • Many small chunks. Chunks read at the same time share requests when they lie at most the policy’s coalescing gap apart in one source file (Policy.max_coalesce_gap, 64 KiB by default), but zarr asks for only async.concurrency chunks at once (10 by default), which limits how many can share one. Raising it makes both fewer requests and a faster read, and opens no more connections, since max_concurrency bounds those. The setting is zarr’s, and applies to the other stores of the process too:

    with zarr.config.set({"async.concurrency": 1024}):
    plane = array[0]

    At the default, the requests fall by up to tenfold but the read takes about as long.

Publishing¶

rewrite_urls=refkv.public_s3_url gives HTTPS URLs that any reader can read without credentials: refkv in Python, the JavaScript reader, and a browser (if the bucket allows cross-origin requests). Serve the archive over HTTPS, and anyone can open it with xr.open_zarr(refkv.zarr.open("https://example.org/oisst.vzip")). save(..., relative_to="https://example.org/data/") writes URLs under that prefix relative to the archive, so the two can move together.

For private data, every reference store takes registry=: the ObjectStoreRegistry you gave VirtualiZarr, or a mapping of URL prefixes to stores, such as obstore’s (pip install "refkv[obstore]", which the virtualizarr extra includes). Readers need the same stores, so tell save_vzip their policy:

from obstore.store import S3Store

registry = {"s3://my-bucket": S3Store("my-bucket", region="us-west-2")}
store = refkv.ReferenceStore.from_virtualizarr(vds, registry=registry)
store.save_vzip("private.vzip", policy=refkv.Policy(schemes={"s3"}))
ds = xr.open_zarr(refkv.zarr.open("private.vzip", registry=registry))

refkv.zarrify.zarrify takes the same registry=, to read the input itself from the bucket: a file, the files it names beside it, or a store (a URL ending in /), each read with the registered store. The result reads its sources with that registry too.

A local input may be its path or its file: URL, as VirtualiZarr passes it, with or without a file:// store in the registry: a file, or a local Zarr v2, Zarr v3 or N5 directory, whose chunks are then references to the directory’s files, named by their file: URLs. The store zarrify returns reads those files, the input’s own, below its directory, and no other local file; a store saved from it is read as below.

from refkv.zarrify import zarrify

store = zarrify("s3://my-bucket/oisst/oisst-avhrr-v02r01.20240101.nc", registry=registry)
store.save_vzip("oisst.vzip", policy=refkv.Policy(schemes={"s3"}))

By default, refkv reads http(s) URLs, and never builds an s3://, gs:// or az:// store itself, so it cannot pick up your cloud credentials by accident. For a private bucket, register its store, as above; that allows its URLs.

A store’s file: sources are refused too, even when you open it from a local path, since a store’s location says nothing about who wrote it, and a store from someone else could otherwise read your files. To read a store’s local files, name them, or allow the scheme for a store you trust:

store = refkv.open("sidecar.vzip", policy=refkv.Policy(prefixes=("file:///data/",)))
store = refkv.open("sidecar.vzip", policy=refkv.Policy(schemes={"file"}))

A prefix list replaces the default, so add "https://" to it if the store also reads the web. A file a symbolic link leads to must be under the prefix too. schemes={"file"} allows every file you can read. A store refkv.zarrify.zarrify has just built reads the files it found without either, as if its prefix list were their directory; once saved, it needs one. The rules are in spec §6.7, Reader policy.

Troubleshooting¶

  • The values are float64, the netCDF file’s float32. Zarr attributes are JSON, so scale_factor and add_offset lose their float32 dtype, and xarray decodes a packed int16 variable as float64 (CF’s rule; pydata/xarray#8713). Every Zarr store does this, to_zarr’s and VirtualiZarr’s included. Cast with ds["sst"].astype("float32"); for OISST this is exact, since an int16 times a float32 scale factor is exact in float64. Or compare packed values with xr.open_zarr(..., mask_and_scale=False).

  • Zarrifying downloads whole files. HDFParser() reads in 1 MiB blocks by default, the whole of a 1.7 MB OISST file. Give it smaller blocks, as the example does, with BlockStoreReader from obspec_utils.readers.

  • Zarrifying is slow, or opens too many connections. Pass parallel= a capped executor class (scaling up).

  • The attributes describe only the first file (its id, time_coverage_start). Pass combine_attrs="drop_conflicts".

  • the scheme 's3' is not allowed (reading) or not saving ...: the default reader policy refuses ... (saving). The references name s3:// URLs, which the default policy refuses. For a public bucket, pass rewrite_urls=refkv.public_s3_url to from_virtualizarr. For a private one, pass registry= to read, and policy=refkv.Policy(schemes={"s3"}) to save_vzip (publishing).

  • no store is registered for s3://.... The policy allows the scheme, but no store serves the URL; pass registry={"s3://bucket": S3Store(...)}, with obstore’s S3Store (refkv[obstore]).

  • an archive reads a local file only when it is allowed. The store names a file: source, which no store reads by default, however it was opened. Pass one of the policies the message gives, if you trust the store with those files.

  • the host is a loopback address (or private, link-local, special), opening an archive or reading a source. refkv refuses requests to addresses on your machine and network by default, an archive’s own included (spec §6.7 rule 3). For an archive you serve yourself, such as http://localhost:8000/data.vzip, pass policy=refkv.Policy(allow_private_hosts=True).

  • the request would go through the proxy .... refkv checks the address each request goes to, and cannot check one a proxy connects to. This holds for an archive’s own URL as well as for its sources, so behind a proxy (http_proxy, https_proxy) opening an https:// archive fails too. Exempt the host with no_proxy, or pass policy=refkv.Policy(allow_unchecked_proxy=True).

  • the value needs more than 2147483648 bytes .... A reader refuses a get of more bytes than its policy allows, 2 GiB by default (spec §6.7 rule 5). VirtualiZarr and kerchunk present a contiguous HDF5 or netCDF variable as one chunk, which can be larger. For a store you trust, pass policy=refkv.Policy(max_get_bytes=...) with a larger bound.

The docstrings say more: help(refkv.ReferenceStore), help(refkv.zarr.open) and help(refkv.vzip.VZipStore) (its registry= and max_concurrency=), and help(refkv.Policy). Without zarr, a store answers get, classify, raw and list itself: refkv.open("oisst.vzip").get("zarr.json").
