MRC as a dataset¶

The dataset layout (conventions §9) of an MRC2014 file: the group dataset that the MRC convention’s hierarchy (mrc.md) also holds, which xarray opens as a dataset with named dimensions and coordinates in angstroms. It is written by the MRC profile (mrc.md §8) beside the image layout, from the same read of the file, and references the same bytes. What all of refkv’s conventions share is in spec/conventions.md, cited here as “conventions §n”; “the MRC convention §n” is a section of mrc.md.

Convention version: 0 (until release, conventions §1) · UUID: f139bf4e-7bab-4c3c-9b2d-66ba747f9b93 · Schema: schema.json

Changes: changes/mrc-dataset/, one file per change.

Changes before 2026-10-22 are recorded in the revision log of VIRTUALIZE.md, this document’s earlier name, up to revision 29.

1. Declaration¶

The group dataset, a child of the root, declares the convention by conventions §2 and §9, with "profile": "mrc-dataset", "version": 0, the file’s URL as source.url, and the source metadata of §4 as the member "mrc-dataset". Its CMO is:

{
  "uuid": "f139bf4e-7bab-4c3c-9b2d-66ba747f9b93",
  "schema_url": "https://d-v-b.github.io/refkv/spec/zarrify/mrc-dataset/schema.json",
  "spec_url": "https://d-v-b.github.io/refkv/spec/zarrify/mrc-dataset.html",
  "name": "refkv_zarrified",
  "description": "The Zarr layout of a MRC dataset source zarrified by refkv, and the source's metadata"
}

The root of the hierarchy, which declares the MRC convention, names this group as "layouts": {"dataset": "dataset"} (conventions §2). The group’s arrays have no attributes but those of §2 and §3.

2. The data variable¶

dataset/data holds the file’s values: the array of the MRC convention §4.1, with the same shape, data type, chunk grid, codecs and fill value, and the same chunks, each the same reference as the image layout’s chunk at the same coords, or the same copied bytes (the MRC convention §8.2). Its dimensions are, by the kind of file, with S, R and C the names the axis map gives the sections, the rows and the columns (the MRC convention §4.1: z, y, x for the standard map):

kind

dimension_names

image

[R, C]

image stack

["section", R, C]

volume

[S, R, C]

volume stack

["volume", S, R, C]

The sections of an image stack are independent images and the volumes of a volume stack independent volumes, so their index dimensions say so rather than borrowing a spatial or temporal name.

3. Coordinates¶

Each of the dimensions x, y and z that the data variable has, and along which the file has a voxel size s (the MRC convention §4.2), has the coordinate variable dataset/<a>, of the dimension’s length n, whose position at index i is o + i × s, where o is the first value’s position p along that axis when the image layout has a translation (the MRC convention §4.2: a volume or a volume stack whose origin is finite and not all 0), and 0 otherwise. These are regular steps, stored as the index (conventions §9): a uint32 array of 0 … n − 1. A CF-decoding reader sees i × s + o in binary64. A dimension without a voxel size, and the index dimensions section and volume, have no coordinate variable.

4. Source metadata¶

The group’s source metadata "mrc-dataset" is the object of the MRC convention §5.1, an MrcRoot, member for member (byte_order, kind, data_type, header, axis_map, voxel_size), so that the group describes its source by itself. The file’s IR mirror is the root’s refkv_source (the MRC convention §5.2); the group has none.

5. Example¶

The volume of the MRC convention §6 (the fixture fixtures/mrc/mrc_volume_float32_le.mrc, 4 × 3 × 2 float32 voxels of 1.5 angstroms, origin (-1.5, 2, 7.25)) has, beside its image layout, the group dataset with the arrays data ([2, 3, 4], dimensions z, y, x, the chunk dataset/data/c/0/0/0 the range (1024, 96) of source 0, as 0/c/0/0/0 is), z ([7.25, 8.75]), y ([2, 3.5, 5]) and x ([-1.5, 0, 1.5, 3]), each stored as the index 0 … n − 1 with scale_factor 1.5 and its add_offset, with {"units": "angstrom"}, and in xarray:

<xarray.Dataset>
Dimensions:  (z: 2, y: 3, x: 4)
Coordinates:
  * z        (z) float64 7.25 8.75
  * y        (y) float64 2.0 3.5 5.0
  * x        (x) float64 -1.5 0.0 1.5 3.0
Data variables:
    data     (z, y, x) float32 ...

An image stack of 20 sections (the fixture mrc_chunk_sections.mrc, whose cella along z is 1, its one section’s) has data with the dimensions section, y, x, coordinates y and x, and no coordinate for section, a stack’s index (conventions §9).
